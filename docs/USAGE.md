# 使用说明 / Usage

[中文首页](../README.md) · [English home](../README.en.md) · [Windows 中文](WINDOWS.md) · [Windows English](WINDOWS.en.md)

先按首页安装 App，在“接入”页复制提示词交给 Agent，再完成本机授权与配对；普通使用无需源码构建。App 默认 profile 为 `default`。本页 CLI 示例使用已配对的 `codex` profile；运行时统一替换为你实际使用的 profile，并将占位 ID 替换为命令返回的值。Windows 在便携包目录中将 `computer-use` 换为 `& .\bin\node.exe .\runtime\cli.js`。

Install the App, copy the setup prompt from Connect to your Agent, and complete local permissions and pairing as described in the README. No source build is needed for normal use. The App defaults to the `default` profile; CLI examples on this page use an existing `codex` profile. Consistently substitute your actual profile and replace placeholder IDs with returned values. On Windows, run from the portable package directory and replace `computer-use` with `& .\bin\node.exe .\runtime\cli.js`.

## App ↔ Skill 双向接入 / Bidirectional onboarding

v0.7.0 的 App 在“接入”页提供“复制安装提示词”。将提示词粘贴给你使用的 Agent，由它获取完整 Skill，按自身支持的方式安装并完成连接验证。用户无需手动保存脚本或选择技能目录。默认 profile 为 `default`；profile 选择、手动配对、MCP 配置和 HTTP 开关放在默认收起的“高级接入”。提示词附带本机路径提示，不含凭据；已有 Skill 自定义内容、profile 和授权范围应保留。

v0.7.0 lets you copy an installation prompt from Connect. Paste it into your Agent; the Agent retrieves the complete Skill, installs it using its own supported mechanism, and verifies the connection. Users do not need to save scripts or choose a Skill directory. The default profile is `default`; profile selection, manual pairing, MCP configuration and HTTP controls are under the collapsed Advanced connection section. The prompt includes non-secret local path hints and preserves existing customizations and grants.

```sh
computer-use preflight --profile default
computer-use instructions
computer-use skill prompt --profile default
computer-use skill export --profile default --out SKILL.md
```

这些命令无需配对、不启动 Host。`preflight` 直接输出 JSON（不带 `--json`），区分 missing、invalid、unverified、valid 和 unauthorized；离线凭据只标记 unverified。Host 在线且验证所选凭据后，支持该字段的新版本还返回 `profile.authorization`（`allApps`、`appIds`、`browser`、`foreground`）；离线、旧服务未提供或字段无效时省略，表示范围未知。`instructions` 返回当前版本说明。`skill prompt` 返回供 Agent 执行安装的提示词；`skill export` 是 Agent 获取完整 Markdown 的底层接口，不带 `--out` 时输出到 stdout，写文件拒绝覆盖。App 不直接写入任何 Agent 的技能目录。

These commands require no pairing and never start the host. `preflight` prints JSON without `--json`; an offline credential is `unverified`, not proof of a valid grant. A supporting online host that authenticates the selected credential also provides `profile.authorization` (`allApps`, `appIds`, `browser`, `foreground`). Offline, older-host or malformed-field responses omit it, leaving scope unknown. `instructions` supplies the installed guide. `skill prompt` supplies the Agent setup prompt; `skill export` remains the underlying Markdown interface for Agents, with optional `--out` that never overwrites an existing file. The App does not write to Agent-specific Skill directories.

仅持有 Skill 时按内嵌平台脚本先发现 App，确实未安装才从官方最新正式发布校验并安装。首次系统权限和配对仍由用户批准；然后用同一 profile 执行 doctor、targets 和实际 observe。v0.6.1 缺新命令时使用内置兼容指南，不能误判为未安装；旧 macOS 包需要本机检查状态或升级后使用受控启动。

With only the Skill, run its embedded platform script to discover an existing App or verify and install the latest official stable package. System permissions and pairing still require local user approval; then verify with doctor, targets and an actual observe. The Skill falls back to its embedded guide for v0.6.1 instead of reinstalling because new commands are absent. Older macOS packages require local state review or an upgrade for controlled startup.

## 后台按需启动 / Background on-demand startup

Windows 自 v0.6.1、macOS 自 v0.7.0 起，同包 CLI 在默认 IPC 不可达时可受控启动宿主，等待就绪后才发出实际 RPC。stdio MCP 的初始化与工具列表不启动宿主；首次实际工具调用才检查。源码运行、自定义 `--socket` 和远程 HTTP 不自动启动。macOS 缺少系统权限时返回 `permissions_required`，不会后台弹出权限窗口。 / Since v0.6.1 on Windows and v0.7.0 on macOS, the packaged CLI can start its same-bundle host when default IPC is unavailable, then send the original RPC once ready. MCP initialization and tool listing stay lazy. Source execution, custom sockets and remote HTTP never auto-start. Missing macOS permissions return `permissions_required` without opening a background permission window.

自 v0.7.0 起，两端的暂停和紧停在退出、重新打开、登录和更新后均保留，只能在 App 内点击“恢复／重启服务”解除。按需启动不会重启已运行但失败的 Host；v0.7.1 可使用下述显式故障恢复命令。不要删除 `host-state.json`、换管道或重装来解除状态。启动失败时未发送原 RPC；已发送动作的失败仍需按原 requestId 查询，不能重放。 / Since v0.7.0 on both platforms, pause and emergency stop survive exit, reopening, login and updates. Only the App's Resume/Restart Services controls clear them. On-demand startup does not restart a live failed host; v0.7.1 provides the explicit fault-recovery command below. Never delete state, switch pipes or reinstall to bypass it. Startup failures send no original RPC; dispatched actions still require their original requestId and must not be replayed.

同包 `ComputerUse.WindowsHost.exe --ensure-running` 可单独检查启动，最多等待 35 秒，stdout 返回单行 JSON：成功 `{"ok":true,"state":"ready"}`，退出 0；失败 `{"ok":false,"code":"…","message":"…"}`，退出非零。`paused` / `stopped` 需用户恢复，`failed` 查看宿主状态，`non_interactive` 表示应在当前用户交互桌面运行，`timeout` / `launch_failed` 需检查错误及系统提示。它不会批准配对或解除 SmartScreen / Smart App Control 拦截，详见 [Windows 指南](WINDOWS.md#按需启动与暂停保护)。 / The bundled `ComputerUse.WindowsHost.exe --ensure-running` checks startup separately, waiting up to 35 seconds and returning one JSON line: `{"ok":true,"state":"ready"}` with exit 0, or `{"ok":false,"code":"…","message":"…"}` with a nonzero exit. `paused` / `stopped` require user recovery; inspect host status for `failed`; `non_interactive` requires the current user's interactive desktop; inspect errors and system messages for `timeout` / `launch_failed`. It does not approve pairing or remove SmartScreen / Smart App Control blocks. See the [Windows guide](WINDOWS.en.md#on-demand-startup-and-pause-protection).

## 通用故障恢复 / General fault recovery

每个新的 Agent 对话首次使用 Computer Use 时，先读取已验证安装包的 CLI `--help`，再执行并阅读受支持的 `instructions`。已有 Skill 或 profile 不能替代当前版本指南；命令或服务兼容性出现问题时重新读取。旧版本没有 `instructions` / `recover` 时使用 Skill 内嵌兼容说明，故障由用户在本机 App 处理，不以重新安装或普通启动绕过停止状态。

At the first Computer Use operation in every new Agent conversation, read the verified installed package's CLI `--help`, then run and read `instructions` when supported. An existing Skill or profile does not replace the current guide; reread it after a command or service compatibility problem. Older packages without `instructions` / `recover` use the Skill's embedded fallback and local App recovery, without reinstalling or launching another way to bypass a stop.

v0.7.1 的 `recover` 适用于所有 Agent。先保留不确定动作的原 requestId、查询 `action_status`，并读取 `preflight --profile NAME`；服务不可达时，恢复后补查原请求。在已授权任务中，Host 为 `failed`，或桌面动作 unknown 后连接丢失且没有用户停止状态时，使用同一完整安装包和已有 profile 自主尝试一次：

The v0.7.1 `recover` command is shared by all Agents. Preserve an uncertain action's original requestId, query `action_status`, and read `preflight --profile NAME`; if unreachable, query the original request again after recovery. Within an authorized task, when the Host is `failed`, or its connection is lost after an unknown desktop action without a user stop, make one autonomous attempt with the same complete package and existing profile:

```sh
computer-use recover --profile NAME
```

只恢复服务故障，不重启健康服务、不重新配对、不扩大或恢复已撤销授权；暂停、紧停、缺失系统权限、非交互桌面和无效状态仍需本机处理。源码执行、自定义 `--socket` 和远程 HTTP 不支持此命令。失败、限流或下一步再次故障时报告原因，不循环尝试。`executed` / `unconfirmed` 只需观察，过期快照需重新观察，不应因此恢复服务。

Recovery repairs faults only: it leaves a healthy service running, never re-pairs, and neither expands nor restores revoked grants. Pause, emergency stop, missing system permissions, a non-interactive desktop and invalid state still require local action. Source execution, custom `--socket` and remote HTTP do not support this command. On failure, rate limiting or another immediate fault, report the cause instead of looping. An `executed` / `unconfirmed` action needs observation, and a stale snapshot needs a fresh observation, not recovery.

成功返回 `actionsReplayed: false`、`requiresNewSession: true`、`requiresFreshObservation: true`，只证明服务可用。旧会话、元素 ID 和快照不能继续使用；新建后台会话并观察实际结果，再决定安全的下一步。原 `unknown` 仍是不确定结果，不能换 UUID、会话、坐标或等价动作重放；画面或文字未变也不能证明点击／按键未送达。无法确认有后果的操作是否发生时交回用户判断。

Success reports `actionsReplayed: false`, `requiresNewSession: true` and `requiresFreshObservation: true`, establishing service availability only. Do not reuse old sessions, element IDs or snapshots: open a new background session and observe before deciding the next safe step. An original `unknown` stays uncertain; never replay it with another UUID, session, coordinate or equivalent action. Unchanged visuals or text do not prove that a click or key was not delivered. If observation cannot establish whether a consequential action occurred, ask the user to resolve it.

macOS 实机与 Windows 隔离检查的范围见[故障恢复验收](validation-fault-recovery-20261012.md)；Windows 真实 Agent / driver 故障恢复尚未验收。 / See [fault-recovery validation](validation-fault-recovery-20261012.md) for macOS desktop and isolated Windows checks; Windows recovery with a real Agent and desktop driver remains unverified.

## 配对范围 / Pairing scope

从 v0.6.0 起，新配对默认一次授权所有桌面应用；首次在本机宿主批准后，新应用、新窗口、会话过期和宿主重启都不需要重复配对。macOS 的辅助功能与屏幕录制权限仍需在系统中授予 Computer Use。 / Since v0.6.0, new pairings default to one grant for all desktop applications. After initial approval in the local host, new apps, new windows, expired sessions and host restarts do not require pairing again. macOS Accessibility and Screen Recording still need to be granted to Computer Use in system settings.

```sh
computer-use pair --profile my-agent --name 'My Agent'
```

| 配对参数 / Pairing options | 授权范围 / Scope |
|---|---|
| 无 / None | 所有桌面应用，等同 `--all-apps`。 / All desktop applications, equivalent to `--all-apps`. |
| `--all-apps --browser` | 所有桌面应用及独立浏览器。 / All desktop applications and the isolated browser. |
| `--app <app-id>` | 高级受限模式，仅指定应用，可重复；macOS 用 Bundle ID，Windows 用完整可执行文件路径，可加 `--browser`。 / Advanced restricted mode for specified apps; repeat as needed. Use Bundle IDs on macOS and full executable paths on Windows; optionally add `--browser`. |
| `--browser` | 仅独立浏览器，不包含桌面应用。 / Only the isolated browser, without desktop applications. |

`--all-apps` 与 `--app` 不能同时使用。全应用授权包含桌面浏览器窗口，但不自动包含 Playwright 独立浏览器。配对批准包含前台权限，执行默认仍为 `background`，不自动切换前台。可随时在“客户端”页撤销授权，菜单中的暂停/恢复与紧急停止继续有效。 / `--all-apps` cannot be combined with `--app`. All-application access includes desktop browser windows but does not automatically include the isolated Playwright browser. Pairing includes foreground permission; execution still defaults to `background` without automatic fallback. Revoke access on the Clients page, or use Pause/Resume and Emergency Stop from the host menu.

旧版本配对与显式受限配对保留原授权范围，不自动扩权。在 App 的“客户端”页选中该客户端，点击“允许所有应用”，本地确认后即可覆盖当前及未来桌面应用，并包含前台操作权限；原 token、profile 和 MCP 配置继续可用，独立浏览器权限保持不变。以 App 的保存成功反馈和随后同一 profile 的检查结果为准。旧 App 没有该按钮时，先升级 App 或由用户在本机复核，Agent 不自动删除凭据或重新配对。现有全应用且已有前台权限的 profile 不需要升级或再次配对。 / Existing pairings and explicit scoped pairings keep their original grants without automatic expansion. Select the client on the App's Clients page and choose Allow all apps. Local confirmation grants current and future desktop applications plus foreground control, preserving the token, profile and MCP configuration while leaving isolated-browser permission unchanged. Wait for the App to confirm persistence, then check the same profile. If an older App lacks this control, upgrade or request local user review; Agents never remove credentials or re-pair automatically. A profile already granting all desktop apps and foreground control needs no upgrade or new pairing.

此升级只面向已有桌面授权的客户端；仅独立浏览器的客户端不能通过该按钮获得桌面权限，应由用户在本机复核所需连接。 / This upgrade is limited to clients that already have desktop access. Browser-only clients cannot acquire desktop permission through this control; the user must review the intended connection locally.

新版 App 也接受 Agent 发起的升级请求：`capabilities.grantRequests` 为 `true` 时，Agent 调用 `request_all_apps`，App 弹出确认框，显示客户端名称、短标识和现有范围，默认按钮是拒绝；用户作答（最多 60 秒）后调用返回，拒绝或过期时返回 `permission_denied`。批准与“客户端”页的按钮效果相同。`preflight`、`doctor` 与 `capabilities` 返回 `client.shortId`（客户端标识的前 8 位，不是凭据），“客户端”页的“标识”列显示同一个值，用来认出同名客户端。宿主启动时声明自己支持这个确认框；旧 App 不声明，运行时就不发出请求，Agent 收到 `unavailable` 后改为请用户在“客户端”页操作。 / Newer Apps also accept an upgrade request from the Agent: when `capabilities.grantRequests` is `true`, the Agent calls `request_all_apps`, and the App shows a confirmation with the client's name, short ID and current scope, with denial as the default. The call returns after the user answers (up to 60 seconds); denial or expiry returns `permission_denied`. Approval has the same effect as the Clients page button. `preflight`, `doctor` and `capabilities` report `client.shortId` (the first 8 characters of the client ID, not a credential), and the Clients page shows the same value in its ID column so clients with the same name can be told apart. The host declares at startup that it can show this confirmation; older Apps do not, so the runtime never sends them the request, and the Agent receives `unavailable` and asks the user to use the Clients page instead.

`doctor` 与 `capabilities` 的 `authorization` 返回当前客户端的实际范围；在线 `preflight.profile.authorization` 提供相同信息。`targets` 只列出此范围内的窗口，未授权应用的窗口会完全省略。窗口缺失时先检查 `allApps` 和 `appIds`，不要把范围限制误判为应用没启动、系统权限丢失或需要逐窗授权。旧服务缺少 `authorization` 时范围未知，通过 App“客户端”页核对。 / The `authorization` field in `doctor` and `capabilities` reports the current client's actual grant; online `preflight.profile.authorization` reports the same scope. `targets` omits windows outside that grant entirely. Check `allApps` and `appIds` before interpreting a missing window as an application launch problem, missing system permission or a need for per-window approval. Older hosts without `authorization` leave scope unknown; inspect the App's Clients page.

在已授权任务与客户端范围内，切换应用、窗口、新建会话或重连均不重复询问。默认使用后台；确实需要前台且客户端已获准时，Agent 简短告知将使用真实鼠标和键盘后即可执行，同一轮连续操作不逐窗确认，结束时告知。发现用户正在操作同一控件、用户要求停止或任务超出原授权范围时暂停协调。此规则不解除暂停、紧停、撤销、系统权限或显式 `--app` 限制。 / Within the authorized task and the client's grant, switching applications or windows, opening sessions and reconnecting do not require another approval. Use background mode by default. When foreground input is needed and permitted, the Agent gives a short notice before using the real mouse and keyboard, proceeds without another approval, and announces completion; one continuous period of control needs no per-window confirmation. Pause to coordinate when the user is using the same controls, asks for a stop, or the task would expand beyond the original authorization. This does not override pause, emergency stop, revocation, system permissions or explicit `--app` restrictions.

## 手动 CLI 流程 / Manual CLI flow

```sh
computer-use doctor --profile codex
computer-use targets --profile codex
computer-use schema act
computer-use session_open --profile codex --json '{"targetId":"TARGET_ID"}'
computer-use observe --profile codex --json '{"sessionId":"SESSION_ID"}'
```

在一次性测试文档中操作：将下面内容保存为 `request.json`，填入当前会话、新快照和该快照中的文本控件 ID。每个新动作使用新的 UUID。CLI 可在省略 `requestId` 时自动生成；MCP 调用必须提供。

Use a disposable test document. Save the following as `request.json` with the current session, a fresh snapshot and its text element ID. Use a new UUID for each new action. CLI generates `requestId` if omitted; MCP callers must supply it.

```json
{
  "sessionId": "SESSION_ID",
  "snapshotId": "SNAPSHOT_ID",
  "requestId": "be9fefc8-ff22-46a8-80b0-05cd50c54129",
  "action": { "type": "type", "elementId": "ELEMENT_ID", "text": "Hello，世界！" },
  "verify": { "type": "element", "valueIncludes": "Hello，世界！", "present": true },
  "observe": { "changes": true }
}
```

```sh
computer-use act --profile codex --input request.json
computer-use session_close --profile codex --json '{"sessionId":"SESSION_ID"}'
```

`verify` 按控件读回的值确认文本已写入；`observe` 让结果直接带上动作后的新快照，`changes: true` 时只列出相对所用快照新增或变化的元素。不带 `observe` 时，下一步前另行调用 `observe`。

`verify` confirms the text through the control's read-back value. `observe` returns the next snapshot with the result; with `changes: true` it lists only elements added or changed since the acted snapshot. Without `observe`, call `observe` before the next step.

CLI 返回截图的本机私有文件路径；MCP 返回图片内容。用新观察或目标程序独立输出确认结果。`executed` 只表示执行阶段结束；大多数桌面动作同时带 `effect: "unconfirmed"`，表示输入已派发但驱动无法证明效果，重新观察即可继续。显式可观察条件通过才返回 `verified`；它也只证明所指定条件，不证明整个任务成功。

CLI returns a private local screenshot path; MCP returns image content. Confirm effects with a fresh observation or the application's independent output. `executed` means execution ended; most desktop actions also carry `effect: "unconfirmed"`, meaning input was dispatched but the driver could not prove its effect, so observe and continue. `verified` requires an explicit observable condition and only establishes that condition.

若连接中断或结果不确定，保留原请求 ID，查询后再观察，不以新 ID 重发同一操作：

After a disconnect or uncertain result, retain the original request ID, query it and observe; do not resubmit the same operation with a new ID:

```sh
computer-use action_status --profile codex --json '{"requestId":"be9fefc8-ff22-46a8-80b0-05cd50c54129"}'
```

## 会话与动作 / Sessions and actions

| 规则 / Rule | 说明 / Behavior |
|---|---|
| 快照 / Snapshots | 坐标是截图像素；动作消费快照，下次操作前重新观察，或在 `act` 里带 `observe` 直接取回新快照。有效期 30 秒，不能检测所有视觉变化。 / Coordinates are screenshot pixels. Actions consume snapshots; observe again before the next action, or pass `observe` to `act` to receive the next snapshot. Snapshots expire after 30 seconds and cannot detect every visual change. |
| 窗口位置 / Window state | 桌面目标不在屏幕上时带 `offScreen`（列出目标时的状态，观察结果里不再沿用）：`minimized` 已最小化，`other-space` 在别的桌面（Space），`not-visible` 其他原因看不见（应用被隐藏、辅助窗口等）。这类窗口上元素动作仍可用（驱动走辅助功能接口）；坐标动作需要窗口在屏幕上，按键也可能被驱动拒绝，返回 `background_unavailable`。本项目没有针对全屏应用和弹出菜单窗口的实机验收。 / Desktop targets that are not on screen carry `offScreen` (the state when targets were listed; observations do not repeat it): `minimized`, `other-space` (another desktop) or `not-visible` (hidden app, helper window and the like). Element actions still work on such windows because the driver uses the accessibility interface; coordinate actions need the window on screen, and keys may also be refused with `background_unavailable`. Full-screen apps and pop-up menu windows have no desktop validation in this project. |
| 会话 / Sessions | 默认后台、独占，两分钟无活动过期；重新打开会话无需再次授权。前台权限在首次配对时一并授予，使用时显式指定 `mode: "foreground"`，不再逐会话批准，不自动切换模式。 / Background and exclusive by default; expire after two idle minutes without requiring a new grant to reopen. Foreground permission is granted at initial pairing and requires explicit `mode: "foreground"`, with no per-session prompt or automatic fallback. |
| 元素 / Elements | 元素 id 由运行时分配：同一会话内角色、标签和位置不变的元素沿用原 id，但动作仍要使用当前 `snapshotId`。可读时给出 `value`（最多 2000 字符，截断时附 `valueLength`）、`enabled: false`、`selected: true` 和 `min`/`max`。密码内容不会返回：macOS 安全文本框和浏览器密码框没有 `value`，只含掩码字符的值也会丢弃；Windows 上 UI Automation 读不到密码框内容，但 WinForms 密码框会把本地化的“拒绝访问”占位文字当作值上报。桌面驱动不报告空文本框的值，`value: ""` 只在独立浏览器中能验证。`elementsComplete: false` 时，没列出某元素不能证明它不存在，负向验证会被拒绝。 / Element IDs are assigned by the runtime and stay the same within a session while an element's role, label and position are unchanged; actions still need the current `snapshotId`. When readable, elements carry `value` (up to 2000 characters, with `valueLength` when truncated), `enabled: false`, `selected: true` and `min`/`max`. Password contents are never returned: macOS secure text fields and browser password inputs carry no `value`, and mask-only values are dropped; on Windows, UI Automation cannot read password boxes, but WinForms reports a localized "access denied" placeholder as the value. Desktop drivers omit empty text values, so `value: ""` can only be verified in the controlled browser. An incomplete element tree cannot establish absence; negative verification is rejected. |
| 观察内容 / Observation parts | `observe` 的 `screenshot: false` 或 `elements: false` 只省略返回内容，快照照常可用。`since` 填你已拿到元素列表的快照 ID，结果只含新增或变化的元素，`changes.removed` 列出消失的 id；没有 `changes` 字段时列表是完整的。`elementsOnly: true` 则根本不抓取截图，更快：这份快照没有截图、像素尺寸和元素位置，只能用于元素点击、输入和按键；坐标点击、拖拽和滚动会被拒绝（`invalid_request`），也不能与 `screenshot: true` 或 `elements: false` 同用。macOS 上点击不支持 AXPress 的文本框要用元素位置，同样会被拒绝，请改用带 `elementId` 的 `type`。`wait` 同样支持 `elementsOnly`；`act` 的 `verify` 在没有附带观察、或附带的观察是 `elementsOnly` 时，轮询也不再抓截图。`act` 带 `observe` 时结果附带动作后的观察，但结果为 `unknown` 时不附带；观察失败时给 `observationError`，重复提交同一请求不再附带。 / `screenshot: false` or `elements: false` only omits that part; the snapshot stays usable. `since` takes the snapshot ID whose element list you already have and returns only added or changed elements, with `changes.removed` listing IDs that disappeared; without a `changes` field the list is complete. `elementsOnly: true` does not capture a screenshot at all, which is faster: that snapshot has no screenshot, pixel size or element bounds and supports element clicks, typing and keys only. Coordinate clicks, drags and scrolls are rejected (`invalid_request`), and it cannot be combined with `screenshot: true` or `elements: false`. On macOS, clicking a text field that does not support AXPress needs its element bounds and is rejected too; use `type` with its `elementId` instead. `wait` accepts `elementsOnly` as well, and `act`'s `verify` polls without screenshots when no observation is attached or the attached one is `elementsOnly`. `act` with `observe` attaches the next observation, except after an `unknown` outcome; `observationError` explains a failed observation, and a repeated request does not attach one. |
| 验证条件 / Conditions | 元素条件可按 `label`、`value`（完整值相等）或 `valueIncludes` 匹配，并可加 `role`、`enabled`、`selected`。值比较不受观察截断影响，换行符统一处理；未报告的值或状态不算满足。这些状态条件只能配 `present: true`。 / Element conditions match `label`, `value` (exact full value) or `valueIncludes`, optionally with `role`, `enabled` and `selected`. Value checks use the full value regardless of observation truncation and normalize line endings; unreported values or states never match. State checks require `present: true`. |
| 点击 / Click | `elementId` 与 `point` 二选一。Windows 元素点击始终走后台辅助功能路径；批准的前台会话中坐标点击走前台指针路径。`modifiers`（`cmd`、`shift`、`option`、`alt`、`ctrl`，最多 4 个）在点击期间按住修饰键：桌面上驱动只在前台投递时才把修饰键交给系统，所以只能在前台会话里发出，后台会话在派发前以 `background_unavailable` 拒绝；带 `elementId` 时点击元素的中心像素，需要带截图的快照，元素被禁用或没有完整可见的位置时拒绝。Windows 没有 `cmd`，`option` 按 `alt` 处理。浏览器不需要前台，修饰键在点击前按下、点击后放开；注意 macOS 上的 Chromium 把 Ctrl 加点击当作右键。桌面上的修饰键点击只有单元测试，没有实机验收。 / Choose either an element or a point. Windows element clicks use background accessibility; point clicks use the pointer in an approved foreground session. `modifiers` (`cmd`, `shift`, `option`, `alt`, `ctrl`, up to four) hold keys during the click. On the desktop the driver passes modifier state to the system only for foreground delivery, so they work in a foreground session only; a background session is refused before dispatch with `background_unavailable`. With an `elementId` the element's centre pixel is clicked, which needs a snapshot with a screenshot, and a disabled element or one without a fully visible position is refused. Windows has no `cmd`, and `option` is sent as `alt`. The browser needs no foreground: modifiers are pressed before the click and released after it; note that Chromium on macOS treats Ctrl plus click as a right click. Desktop modifier clicks are unit-tested only, with no desktop validation. |
| 输入 / Type | Windows 元素定向输入即使在前台会话也走后台辅助功能路径；不确定或拒绝后不换路径、不重发。无元素 ID 的前台长文本未获完整性保证。macOS 上网页内容（浏览器、Electron、Tauri、终端）逐键接收文字，后台约每秒 25 字、另有约 4 秒启动，前台更慢：运行时按此估算，`timeoutMs` 内打不完的文字在派发前以 `invalid_request` 拒绝，什么都不发出。前台超过 64 字的文字分段输入，每段之间检查剩余时间和用户是否在用鼠标键盘，停下时结果带 `progress`（已完整送达的 `delivered` / `total` 字符数）和警告 `partial_input`。网页里会自行清空的输入框（xterm.js 等终端）读不回文字，驱动报告“未送达”，但实测文字完整到达：运行时记为 `executed` / `unconfirmed` 并带警告 `readback_mismatch`，不停机。驱动报告输入预算不足时，动作在发出任何字符前以 `invalid_request` 失败，并给出可接受的分段长度。 / Windows element-directed typing uses background accessibility even in foreground sessions, without fallback or retry. Long foreground text without an element ID is not guaranteed. On macOS, web content (browsers, Electron, Tauri, terminals) receives text as keystrokes, about 25 characters per second in the background after roughly 4 seconds' start and slower in the foreground. The runtime estimates this and refuses text that cannot finish within `timeoutMs` before dispatch with `invalid_request`, sending nothing. Foreground text over 64 characters goes in parts; between parts the runtime checks the remaining time and whether the user is using the mouse or keyboard, and when it stops the result carries `progress` (`delivered` of `total` characters fully sent) and warning `partial_input`. Self-clearing web inputs (xterm.js terminals and the like) cannot read the text back, so the driver reports it undelivered although it arrived in full in testing: the runtime records `executed` / `unconfirmed` with warning `readback_mismatch` and keeps running. When the driver reports its typing budget exceeded, the action fails with `invalid_request` before any character is sent and names the part length it accepts. |
| 粘贴 / Paste | `paste` 先在宿主的辅助进程里保存用户剪贴板的全部条目和格式，写入文字（带临时、敏感、自动生成标记，不同步到其他设备，不进入剪贴板历史），粘贴后约 0.8 秒恢复；期间用户复制了新内容时保留新内容并给出 `clipboard_not_restored`，有格式没能保存时给出 `clipboard_partial`。剪贴板内容只留在辅助进程里，不进入运行时、日志或结果。末尾换行会去掉。macOS 后台会话调用应用的“粘贴”菜单命令（未激活的应用不处理 ⌘V，实测 WebKit 页面收不到），送到该应用当前焦点所在的输入框，因此不接受 `elementId`，应用没有可用的“粘贴”菜单命令时以 `background_unavailable` 失败；前台会话和 Windows 发送粘贴快捷键。macOS 首次保存剪贴板时系统可能询问用户是否允许 Computer Use 读取剪贴板，拒绝时以 `permission_denied` 失败、什么都不粘贴；`restoreClipboard: false` 不读取也不恢复。 / `paste` saves every item and format of the user's clipboard inside a host helper process, writes the text (marked transient, concealed and auto-generated, kept off other devices and out of clipboard history), pastes and restores the clipboard about 0.8 seconds later. If the user copied something else meanwhile, the new content is kept and the result carries `clipboard_not_restored`; formats that could not be saved produce `clipboard_partial`. Clipboard contents stay in the helper process and never reach the runtime, journal or results. Trailing line breaks are removed. In a macOS background session paste runs the app's Paste menu command (an inactive app does not handle ⌘V; a WebKit page received nothing in testing), which goes to the field that has focus in that app, so `elementId` is refused, and an app without a usable Paste menu command fails with `background_unavailable`. Foreground sessions and Windows send the paste shortcut. On macOS the system may ask the user whether Computer Use may read the clipboard the first time it is saved; a refusal fails with `permission_denied` and pastes nothing. `restoreClipboard: false` neither reads nor restores. |
| 文字识别 / Text recognition | `observe` 的 `text: true` 返回截图上识别出的文字行和像素位置；`wait` 与 `act` 的 `verify` 接受 `{"type": "text", "includes": "..."}`，比较时忽略空白，全角与半角、各种横线和引号视为相同。用于终端、canvas 等元素树里没有的文字；识别可能漏字或认错，只能确认出现，不能证明不存在。macOS 用 Vision，先按英文识别（命令和路径更准），系统首选语言不是英文时再按该语言识别一遍、合并含该语言文字的行；一台 Mac 第一次识别要先在本机准备模型（实测约 1 分钟），运行时启动后在后台先做一次，期间的请求等待或返回 `unavailable`。Windows 用系统 OCR，装有英文识别语言时同样两遍；中文识别器会把半角标点认成全角。 / `observe` with `text: true` returns the text lines recognized in the screenshot with pixel bounds; `wait` and `act`'s `verify` accept `{"type": "text", "includes": "..."}`, ignoring whitespace and treating full-width forms, dashes and quotes alike. It is meant for terminals, canvases and other text missing from the element tree; recognition can miss or misread characters, so it confirms presence only, never absence. macOS uses Vision, first in English (more accurate for commands and paths) and, when the first preferred system language is not English, again in that language, merging the lines where it read that language's letters. The first recognition on a Mac prepares a model locally (about a minute in testing); the runtime does it once in the background after starting, and requests meanwhile wait or return `unavailable`. Windows uses the system OCR, also in two passes when an English recognizer is installed; its Chinese recognizer turns ASCII punctuation into full-width forms. |
| 遮挡 / Covered windows | 目标窗口被前面的其他窗口完全挡住时，观察结果带 `covered: true`；窗口里有网页内容时还带 `screenshotMayBeStale: true`，因为网页视图被挡住时可能停止重绘。文字等待在这种窗口上超时时会说明截图可能没有更新。判断按窗口区域网格取点估算，透明或异形窗口也算遮挡。 / When other windows completely cover the target window, observations carry `covered: true`, plus `screenshotMayBeStale: true` when the window shows web content, because a covered web view may stop redrawing. A text wait that times out on such a window says its screenshots may not have updated. Coverage is estimated from a grid of points in the window; transparent or irregular windows count as covering. |
| 用户在操作 / User activity | 前台动作派发前检查用户最近一次键盘鼠标输入（macOS 读 HIDIdleTime，Windows 读 GetLastInputInfo），1 秒内有输入时以 `busy` 拒绝，什么都不发出。 / Before dispatching a foreground action the runtime checks the user's last keyboard or mouse input (HIDIdleTime on macOS, GetLastInputInfo on Windows) and refuses with `busy`, sending nothing, if there was input within the last second. |
| 文本效果 / Text effects | 后端和控件决定具体文本行为，需读回完整内容（元素的 `value`，或 `value` / `valueIncludes` 条件）；不要假定所有路径都追加或替换。浏览器路径使用 `insertText`。 / Read back the full value (the element's `value`, or a `value` / `valueIncludes` condition): do not assume all controls append or replace text identically. The browser uses `insertText`. |
| 设置值 / Set value | `setValue` 用 `elementId` 整体替换元素的值（文本框、滑块、步进器等），不是在光标处插入；走辅助功能接口，不移动焦点，前后台会话都一样。macOS 文本框由驱动读回确认（`effect: "confirmed"`），滑块等读不回的只是发出（`unconfirmed`），都用元素的 `value` 或 `verify` 条件核对。macOS 弹出按钮（NSPopUpButton）会在派发前被拒绝：驱动 0.28.2 对它返回没有错误码的失败，无法证明输入没有发出。浏览器里 `setValue` 替换文本框内容，或按可见文字或值（忽略大小写和首尾空白）选择 `<select>` 的选项，找不到时没有任何改动。Windows 走 UI Automation 的 ValuePattern，只有单元测试，没有实机验收。 / `setValue` replaces the whole value of an element by `elementId` (text fields, sliders, steppers and so on) instead of inserting at the cursor. It uses the accessibility interface, moves no focus and behaves the same in background and foreground sessions. On macOS the driver reads text fields back (`effect: "confirmed"`); controls it cannot read back, such as sliders, are only sent (`unconfirmed`). Check either with the element's `value` or a `verify` condition. macOS pop-up buttons (NSPopUpButton) are rejected before dispatch because driver 0.28.2 fails them without an error code, so it cannot be proven that no input was sent. In the browser, `setValue` replaces text-field content or chooses a `<select>` option by visible text or value (case and surrounding whitespace ignored); an unmatched option changes nothing. Windows uses the UI Automation ValuePattern and is unit-tested only, with no desktop validation. |
| 菜单 / Menu | `menu` 用菜单名路径调用应用菜单项，如 `["File", "Export", "PDF…"]`，各段与菜单上显示的名称完全一致（只忽略首尾空白，区分大小写，注意 `…` 这类符号）。观察结果不列出未展开的菜单内容，所以名称要按应用的实际菜单给出。同样走辅助功能接口，调用本身不移动焦点（菜单命令自己可能弹出对话框或把应用调到前面）。路径缺失、重名或菜单项被禁用时，驱动在派发前拒绝，结果是 `failed` / `not_found`，不会停机。macOS 的系统 Apple 菜单（菜单栏第一项）不对 Agent 开放，调用会在派发前以 `permission_denied` 失败；快照里找不到菜单栏时以 `invalid_request` 失败。驱动读不回菜单命令的效果，成功时是 `executed` / `unconfirmed`，要观察界面或产物确认。浏览器页面没有应用菜单。Windows 只有单元测试，没有实机验收。 / `menu` invokes an application menu item by a path of names such as `["File", "Export", "PDF…"]`. Each segment must match the displayed name exactly (surrounding whitespace is ignored; case matters, and so do symbols like `…`). Observations do not list unexpanded menu content, so give names from the application's actual menus. It uses the accessibility interface and the call itself moves no focus (a menu command may open a dialog or bring its app forward on its own). A missing, ambiguous or disabled path is refused by the driver before dispatch and ends as `failed` / `not_found` without stopping the runtime. The macOS system Apple menu (the first menu bar item) is not available to agents and fails with `permission_denied` before dispatch; a snapshot without a menu bar fails with `invalid_request`. The driver cannot read a menu command's effect back, so success is `executed` / `unconfirmed`: observe the UI or output to confirm. Browser pages have no application menu. Windows is unit-tested only, with no desktop validation. |
| 拖拽 / Drag | 仅两个端点的直线手势。macOS 拒绝后台拖拽；Windows 向驱动传递会话模式，实际支持仍需验证。 / Two-endpoint straight gestures only. macOS rejects background dragging; Windows passes the session mode to the driver, with actual support still requiring validation. |
| 时限 / Deadlines | `timeoutMs`（默认 15 秒、最多 30 秒）同时限定派发和 `verify`；排队超过 15 秒仍未开始的动作直接取消、不派发。输入发出前就到时限时，动作以 `failed` / `timeout` 结束且未发送任何输入；输入已经发出时，再给它最多 5 秒完成，仍未完成才记为 `unknown`。 / `timeoutMs` (default 15 s, max 30 s) bounds dispatch and `verify` together; an action still queued after 15 seconds is cancelled without dispatch. If the deadline passes before input is dispatched, the action ends as `failed` / `timeout` and nothing was sent; input already dispatched gets up to 5 more seconds to finish before it is recorded as `unknown`. |
| 保留 / Retention | CLI 截图文件保留 24 小时，之后在下次观察时删除；动作日志只保留 7 天内、最多 500 条已结束记录；过期会话和快照在后台定时回收。 / CLI screenshot files are kept for 24 hours and removed on a later observe; the action journal keeps at most 500 finished records from the last 7 days; expired sessions and snapshots are reclaimed in the background. |
| 滚动 / Scroll | 方向加 `line` / `page` 单位与 1–50 的数量；浏览器每行 40 CSS 像素。 / Direction, line/page unit and amount 1–50; browser lines are 40 CSS pixels. |

暂停阻止新动作。紧急停止取消工作并关闭执行器；桌面输入发出后被中断或超时引起的不确定结果会停止执行。驱动调用已经正常返回、只是无法判断效果时（例如分段输入的下一段结果不明），记为 `unknown` 但不停止执行。独立浏览器的输入限于隔离页面：不确定结果记为 `unknown`，但不停止执行；导航遇到网络错误时直接返回 `failed`。`unknown` 只表示输入是否送达本身不确定；驱动已完成派发但效果无法确认时返回 `executed` 加 `effect: "unconfirmed"`，不停止执行。重启不重放动作。完整参数以 `computer-use schema <method>` 为准。

Pause blocks new actions. Emergency stop cancels work and closes executors; desktop input that is interrupted or times out after dispatch stops execution. When the driver call returned normally but its effect cannot be determined (for example the next part of chunked typing), the action is recorded as `unknown` without stopping execution. Controlled-browser input is confined to an isolated page: an uncertain outcome is recorded as `unknown` without stopping execution, and a navigation network error returns `failed`. `unknown` means delivery itself is uncertain; completed dispatch with an unconfirmed effect returns `executed` with `effect: "unconfirmed"` and does not stop execution. Restart never replays actions. Use `computer-use schema <method>` for full parameters.

## 独立浏览器 / Separate browser

```sh
computer-use browser install
computer-use pair --profile browser --name 'Browser Agent' --browser
computer-use targets --profile browser
computer-use config codex --profile browser
```

在本地 App 批准浏览器配对后，全程使用 `--profile browser`。首次列目标会创建独立的空白 headless Chromium；不读取日常浏览器登录状态。多个获准客户端共享此浏览器空间。只支持 HTTP(S) 和 `about:blank` 导航，下载到独立目录。JS 对话框自动取消，不代表接受。

Approve browser pairing locally and consistently use the `browser` profile. Listing targets first creates a separate blank headless Chromium without your regular browser login state. Authorized clients share this browser space. Navigation supports HTTP(S) and `about:blank`; downloads use a separate directory. JavaScript dialogs are automatically dismissed, not accepted.

## 配置与排错 / Configuration and troubleshooting

- 所有命令与 Agent 配置使用同一 profile；已有 profile 不重复配对。扩大到所有桌面应用使用 App“客户端 → 允许所有应用”，撤销仍在 App 内完成。`credentials remove` 只删除本地文件，不使凭据副本失效。 / Use the same profile in commands and agent configuration. Do not pair an existing profile again. Expand desktop scope through Clients → Allow all apps; revoke in the App to invalidate credentials. `credentials remove` only removes the local file.
- 移动安装目录后重新生成 `config codex` / `config stdio`，因为配置使用绝对路径。 / Regenerate configuration after moving the installation: launch paths are absolute.
- HTTP 需在宿主设置窗口的“接入”页启用，只在本次运行有效。macOS 可用 `computer-use config http --profile codex --out private-mcp.json` 导出新文件；Windows 必须导出到宿主私有目录，见 Windows 指南。导出的 JSON 含凭据，不能提交或分享。 / Enable HTTP on the Connect page of the host settings first; it lasts for the current run only. On macOS the command above exports a new private file; Windows requires the host's private data directory. Exported HTTP JSON contains credentials and must not be committed or shared.
- 桌面不可达先检查宿主状态、登录会话和系统权限；浏览器不可用先检查匹配的 Chromium。旧快照或元素被拒绝时重新观察，不复用旧坐标。 / For desktop failures check the host, login session and OS grants; for browser failures check matching Chromium. Re-observe after stale snapshot or element rejection rather than reusing coordinates.

两条命令不需要配对凭据，也不需要宿主在运行。`check` 输出 JSON：当前与最新版本、`available`、发布页、纯文本发布说明和本平台安装包（名称、大小、SHA-256）。GitHub API 返回 403、429、5xx 或连不上时（未认证调用每个 IP 每小时 60 次），改由 `github.com/starroyhq/computer-use/releases/latest` 的跳转确定最新正式版，从该版本的元数据资产读取安装包信息，从该标签的 `.github/release-notes/` 读取说明；此时没有 `publishedAt`，下载时也没有 GitHub 摘要可核对。只比较 `MAJOR.MINOR.PATCH` 正式版，草稿、预发布和旧版本都不提供。`download` 会重新读取最新发布；`--release` 与最新版本不同时拒绝下载（避免下载用户没看过的版本）。它下载本平台的 `.zip.sha256` 与 `.json` 元数据，核对版本、平台、提交、干净源码标记、大小、签名方式（macOS 须为已公证的 Developer ID，Windows 为未签名）以及 SHA-256，全部一致才把安装包写入目录；失败时不留下文件。从 v0.6.0 起，在 ZIP 之外提供额外安装包（macOS `.dmg` 用于首次安装，Windows `-setup.exe` 用于首次安装和安装版升级），`check` 的 `installer` 字段描述它；v0.5.0 的历史发布仅提供 ZIP，没有这个字段。macOS App 与 DMG 的公证、装订由发布 CI 验证，本次结果仍待确认；Windows 安装版从真实发布升级的完整流程仍待验收。`--installer` 改为下载安装包，按它自己的 `.sha256`、元数据中的 `installer` 项和 GitHub 摘要校验，最新版没有安装包时拒绝。`--progress` 在 stderr 逐行输出 `{"event":"progress","downloaded":N,"total":M}`。请求只发往 `api.github.com`、`github.com` 与 `*.githubusercontent.com` 的 HTTPS 地址，每次跳转都重新核对主机。 / Neither command needs pairing credentials or a running host. `check` prints JSON with the current and latest versions, `available`, the release page, plain-text notes and this platform's package (name, size, SHA-256). When the GitHub API answers 403, 429 or 5xx or cannot be reached (unauthenticated calls are limited to 60 per hour per IP), the latest stable tag comes from the `github.com/starroyhq/computer-use/releases/latest` redirect, package details from that release's metadata asset and notes from the tag's `.github/release-notes/` file; `publishedAt` is then omitted and downloads have no GitHub digest to compare. Only plain `MAJOR.MINOR.PATCH` releases are compared; drafts, prereleases and older versions are never offered. `download` re-reads the latest release and refuses when `--release` no longer matches it, so a user never receives a version they did not review. It fetches this platform's `.zip.sha256` and `.json` metadata and checks version, platform, commit, clean-source flag, size, signing (notarized Developer ID on macOS, unsigned on Windows) and SHA-256 before writing the package; failures leave nothing behind. Since v0.6.0, additional packages are provided alongside ZIPs (`.dmg` for first installs on macOS, `-setup.exe` for first installs and installed-copy upgrades on Windows), described by the `installer` field of `check`; the historical v0.5.0 release provides ZIPs only and has no such field. Release CI verifies notarization and stapling of the macOS App and DMG; this release's result remains to be confirmed. The complete Windows upgrade flow from a real release still needs acceptance testing. `--installer` downloads that installer instead and checks it against its own `.sha256`, the `installer` entry of the metadata and the GitHub digest, refusing when the latest release has none. `--progress` writes `{"event":"progress","downloaded":N,"total":M}` lines to stderr. Requests go only to HTTPS `api.github.com`, `github.com` and `*.githubusercontent.com`; every redirect is re-checked.

宿主的“更新”页调用同一组命令：自动检查默认每天一次，可关闭或跳过某个版本；macOS 正式版在额外核对 Bundle ID、版本、签名团队和 Gatekeeper 后原位替换并重新打开；Windows 安装版用 `--installer` 下载安装程序，由用户点“运行安装程序”按向导完成，便携版只下载校验 ZIP 并在资源管理器中显示。 / The hosts' Updates page runs the same commands: automatic checks run at most daily and can be turned off or skip a version. Signed macOS releases additionally verify the bundle identifier, version, signing team and Gatekeeper before replacing the app in place and relaunching it. An installed Windows copy downloads the installer with `--installer` and the user runs it through the setup wizard; a portable copy only downloads, verifies and reveals the ZIP.
