## Design decisions
- D1 No-`--profile` behavior: `skill prompt`/`skill export` without `--profile` switch to "agent-chosen" mode: the prompt says `skill export --profile <your-agent-profile>` and tells the agent to pick a stable lowercase slug of its own agent/product identity; the binding JSON omits `profile` and instead carries `"profileSelection": "agent"` (explicit mode writes `"profile": "<name>"` and `"profileSelection": "user"`). Rationale: placeholder text can't be mistaken for a real profile, and the binding stays parseable. Other commands keep `default` (back-compat for existing users/scripts).
- D2 Detect "explicit": remove the parseArgs default for `profile`; compute `profile = values.profile ?? 'default'` for all commands except `skill prompt`/`skill export`, which receive `values.profile` (possibly undefined). `setupPrompt(profile: string | undefined, paths)` and `exportSkill(profile: string | undefined, ...)`. `--out` JSON result prints `profile` only when explicit (else `"profileSelection":"agent"`).
- D3 Prompt/Skill texts must not name any IDE/agent product (no "Kiro", "Claude", "Codex", "Cursor", etc.) and in agent mode contain no `--profile default` / `"profile": "default"`.
- D4 Ownership in preflight, offline: add `profileDetails: Array<{ name, state: 'present'|'invalid', client?: { id, shortId, name? } }>` alongside unchanged `profiles: string[]` and `profile`. For each credential file: parse `clientId` (never output token), `shortId = clientId.slice(0,8)`; `name` comes from best-effort offline read of `<dataDir>/clients.json` (extract only `id`/`name`; ignore `tokenHash` and everything else; files > 1 MiB or unreadable/malformed → names omitted, no error). Also fill `profile.client.name` offline from the same map when not verified online (online identity still wins). Limit documented: offline names reflect the last saved host data, may be stale or missing (e.g., Windows host data under another account, or the file unreadable), and do not prove validity — only an online `valid` state does. No network, no host launch.
- D5 Reuse rule (texts): reuse an existing profile without pairing only if this agent's own installed Skill binding already names it, or its `client.name` identifies this agent. If owned by another client: do not reuse; choose this agent's own profile name (if that is taken by another client, append a suffix like `-2`) and pair it (local user approval required); if ownership is ambiguous (no name available), ask the user. A user-specified profile (explicit `--profile`, binding with `profileSelection: "user"`, or user instruction) is honored as-is. After install the agent records its chosen profile in its installed Skill's local binding (sets `profile`, keeps paths).
- D6 App UI: add an "Let the Agent choose (recommended)" selection, represented as `nil`/empty selection. It is the default when no saved selection exists; in that mode copy-prompt calls `skill prompt` with no `--profile`, preflight is still run with `--profile default` only to list profiles (or skip profile state display), and pair command / MCP configuration show a hint "choose a profile to show" instead of a `default` command. Picking a concrete profile is an explicit choice and is passed verbatim. Existing saved UserDefaults/HostSettings selections are kept (treated as explicit). Rationale: the copy button is the field bug's entry point; agent-neutral by default without breaking users who chose a profile.
